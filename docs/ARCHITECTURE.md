# Архитектура

Проект — статическая браузерная игра без сборщика.

## Основные файлы

- `index.html` — разметка, экран загрузки, навигация и контейнер модальных окон.
- `style.css` — адаптивная вёрстка, состояния элементов, модальные окна и touch-стили.
- `game.js` — игровые данные, состояние, экономика, прогрессия, сохранение, UI, звук и SDK.
- `assets/` — изображения игры.
- `tests/game.test.js` — проверки игрового ядра в Node VM.
- `tests/browser.smoke.cjs` — браузерный smoke-тест в Chromium.
- `scripts/package-release.sh` — сборка и проверка релизного ZIP.

## Организация `game.js`

### Данные

`GARAGES`, `TOOL_NAMES`, `AUTO_NAMES`, `CARS`, `ACHIEVEMENTS` и `TASKS` содержат неизменяемые игровые каталоги.

### Состояние

`defaultState()` создаёт новое сохранение. `normalizeState()` проверяет данные перед использованием и восстанавливает безопасные значения при повреждённом или устаревшем сохранении.

### Экономика

`toolBonuses()`, `carBonus()`, `multiplier()`, `income()` и `clickValue()` рассчитывают основные источники дохода и бонусы.

### Прогрессия

Клики, покупки, задания, заказы, автомобили, гаражи и prestige изменяют состояние игрока. Постоянная статистика хранится отдельно от текущего цикла.

### Сохранение

Основной ключ: `garage_tycoon_idle_v3`.

Поддерживаются `garage_tycoon_v1` и `garage_tycoon_v2`. Сохранение выполняется после важных действий, периодически во время игры, при `beforeunload` и при скрытии страницы.

### SDK

Игра подключает Yandex Games SDK через `/sdk.js` и использует загрузку SDK, Game Ready, Gameplay API, рекламу и определение языка окружения.

Если SDK недоступен, базовый игровой цикл продолжает работать.

### UI

`render()` обновляет интерфейс по dirty-флагу. Большие каталоги открываются в модальных окнах, а основные разделы доступны через нижнюю навигацию.

## Изменения

Перед изменением игровой механики:

1. изменить логику;
2. обновить соответствующие тесты;
3. выполнить `node --check game.js`;
4. дождаться успешного CI;
5. проверить затронутый пользовательский сценарий.
