# Технический аудит

## Назначение

Документ фиксирует состояние проекта перед передачей релизной сборки на ручную проверку.

## Автоматические проверки

- JavaScript проходит `node --check game.js`.
- Core tests проходят.
- Playwright smoke-тест проходит на мобильном viewport.
- Релизный скрипт проверяет структуру ZIP, имена файлов и размер архива.
- CI публикует проверенный ZIP как artifact.

## Что проверить вручную

### Игра

- новый запуск и обучение;
- ремонт, комбо, инструменты и автоматизация;
- задания, достижения, заказы и поставка;
- автомобили, гаражи и prestige;
- offline-доход и профиль;
- сброс прогресса.

### Сохранение

- купить инструмент и перезагрузить страницу;
- купить автоматизацию и перезагрузить страницу;
- изменить гараж и автомобиль и перезагрузить страницу;
- получить награду и перезагрузить страницу;
- скрыть/вернуть страницу;
- сменить ориентацию мобильного устройства.

### SDK и реклама

- проверить Game Ready;
- проверить Gameplay API при запуске, паузе и модальных окнах;
- проверить автоматическое определение языка;
- проверить rewarded video и выдачу награды только после callback;
- проверить fullscreen-рекламу;
- убедиться, что во время рекламы игра и звук остановлены.

### Интерфейс

- проверить заявленные размеры экрана;
- убедиться в отсутствии горизонтального overflow;
- проверить long-tap/context menu;
- проверить отсутствие ошибок в консоли.

## Релизная сборка

Сборка выполняется командой:

```bash
bash scripts/package-release.sh
```

В архив попадают только:

```text
index.html
game.js
style.css
assets/
```

Тесты, документация, CI и служебные файлы в архив не включаются.

## Статус

Техническая сборка проверяется CI. Ручная проверка в окружении площадки остаётся отдельным этапом перед публикацией.
